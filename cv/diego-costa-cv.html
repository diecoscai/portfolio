What I fixed, and why it was hard

The timeout that wasn't there — AnswerAgent

A client's agent was cutting out at five seconds, intermittently. The timeout everyone had configured was a no-op: the MCP subprocess was spawned without inheriting its environment, so the setting never reached it. Behind that, the vectorstore ran one unindexed lookup per result document, so under load the tail crossed the limit. Fixed both.

Users couldn't see their own documents — AnswerAgent

Document chunks were being written with no owner id, so tenant-scoped queries matched nothing. Added the safeguard at write time and a migration to backfill the orphaned rows. Also put runtime guardrails on the public embed endpoint, which had been skipping them because embed requests carry no user.

A manual nobody had written, and the tool that answers from it — SBI Bids

Documented the product screen by screen across all eight workflows, checked against the code, then built the tool that answers "how do I do X" from that manual with a link to the exact section — and says the manual doesn't cover it instead of inventing UI.

Alarms that had been silent since March — internal desktop product

CPU, memory and disk alarms sat in INSUFFICIENT_DATA because nothing was installed to emit the metrics. Built the monitoring, baked the agent into host setup, and moved the alarms into CloudFormation. Also got the Electron app shipping again: signed builds had been failing notarization for a month, and auto-update published one manifest for two architectures, so arm64 users updated into the wrong binary.
